FullTank · PrimeFuel · Edge API

Guía: compilar, correr, desplegar y probar con el sensor

La Edge API recibe las lecturas del ESP32 (por MQTT o HTTP), las valida y las reenvía al backend en Render con el X-Device-Token. El dispositivo nunca tiene ese token.

1Compilar y pruebas unitarias

Desde la carpeta edge/:

Linux / macOS

./mvnw package -DskipTests      # genera target/*.jar

Windows (PowerShell)

Sin Java instalado, Docker compila por ti:

docker build -t fulltank-edge .
  • Las pruebas cubren: validación (deviceId, rango, esquema, hora futura), orden de reenvío, reintentos con backoff, rechazos 4xx, cuarentena, duplicados, cola llena y arranque de la aplicación.

2Configurar

2.1 · Emitir el token del dispositivo (una vez)

  1. Despierta Render abriendo https://fulltank-backend.onrender.com/api (tarda cerca de 1 minuto).
  2. Inicia sesión como distribuidor: 
    curl -X POST https://fulltank-backend.onrender.com/api/authentication/sign-in \
  -H "Content-Type: application/json" \
  -d '{"username":"<usuario>","password":"<clave>"}'
  3. Emite la credencial con el token (JWT) de la respuesta: 
    curl -X POST https://fulltank-backend.onrender.com/api/provider/tanks/<tankId>/device-credential \
  -H "Authorization: Bearer <JWT>"
  4. Guarda token, deviceId y channel de la respuesta. El token se muestra una sola vez. Si responde 409, ya hay uno activo: usa …/device-credential/rotate.

2.2 · Crear .env

cp .env.example .env
VariableValor
DEVICE_TOKENToken del paso 2.1
EDGE_API_KEYClave larga inventada (la usa el ESP32 en modo HTTP)
MQTT_TOPICfulltank/<sufijo-aleatorio>/tanks/+/readings

Nunca subas .envYa está en .gitignore. El token solo debe vivir ahí.

3Correr y desplegar

Opción A · Docker Compose (recomendada)

docker compose up -d --build     # Edge + Mosquitto
docker compose logs -f edge      # ver lecturas en vivo
docker compose down              # apagar

Opción B · Java directo

set -a; source .env; set +a      # Linux/macOS: carga las variables
java -jar target/fulltank-edge-0.0.1-SNAPSHOT.jar

Comprobar

curl http://localhost:8090/health
  • "mqtt": {"connected": true, …}
  • "backend": {"deviceTokenConfigured": true, …}
  • "relay": {"queued": 0, "lastError": null, …}
¿Dónde se despliega?En el PC que está junto al sensor (es una API de borde), con Docker Compose. No va en Render: el plan gratis se duerme a los 15 min y el suscriptor MQTT dejaría de escuchar. Todas sus conexiones son salientes (al broker y a Render), así que no hay que abrir puertos en el router; solo el 8090 en la red local si el ESP32 usa HTTP.

4Contrato para el firmware

MQTT (Wokwi)

  • Broker broker.hivemq.com:1883, sin usuario
  • Topic fulltank/<sufijo>/tanks/<tankId>/readings
  • Mismo sufijo que en MQTT_TOPIC

HTTP (placa real, misma WiFi)

  • POST http://<IP-PC>:8090/api/v1/readings
  • Content-Type: application/json
  • X-Edge-Key: <EDGE_API_KEY>

Cuerpo (igual en los dos)

{"schemaVersion":1,"deviceId":"esp32-tank-1","channel":"level","sequence":1792650000,
 "capturedAt":"2026-10-22T15:00:00Z","level":640.5,"unit":"LITRE"}
CampoReglaSi no se cumple
deviceId, channelExactamente los del registro del tanqueBackend: QUARANTINED
sequenceÚnica y creciente. En Wokwi usar la hora UNIX (la NVS se borra en cada simulación)Se ignora como duplicada
capturedAtUTC por NTP, con Z, nunca en el futuroEdge: 400
levelLitros, entre 0 y la capacidadEdge: 400 · Backend: QUARANTINED
TokenNo se envía desde el ESP32—
Respuesta HTTP de la EdgeQué hace el ESP32
202Lectura entregada
400 / 401Descartar y encender el LED de error (reenviar no cambiaría nada)
Sin respuesta / 5xxReintentar la misma lectura con la misma sequence

5Pruebas, de menor a mayor

5.1 · Edge sola por HTTP (sin ESP32)

curl -X POST http://localhost:8090/api/v1/readings \
  -H "Content-Type: application/json" -H "X-Edge-Key: <EDGE_API_KEY>" \
  -d '{"schemaVersion":1,"deviceId":"<deviceId>","channel":"<channel>","sequence":'$(date +%s)',"capturedAt":"'$(date -u +%Y-%m-%dT%H:%M:%SZ)'","level":500,"unit":"LITRE"}'
  • Responde {"status":"QUEUED",…} con 202
  • docker compose logs edge muestra reenviada: quality=ACCEPTED

5.2 · Edge por MQTT (sin ESP32)

En MQTTX conéctate a broker.hivemq.com:1883 y publica el mismo JSON (con una sequence nueva) en fulltank/<sufijo>/tanks/<tankId>/readings.

  • El log muestra encolada (MQTT) y luego reenviada: quality=ACCEPTED

5.3 · Sensor simulado en Wokwi

  1. Plantilla ESP32 (la clásica, DevKit; no la S3).
  2. Pega el sketch y diagram.json, y agrega la biblioteca PubSubClient.
  3. Configura DEVICE_ID, CHANNEL, TOPIC_SUFFIX y CAPACITY_L.
  4. ▶ Simula y mueve el control de distancia del HC-SR04: un cambio ≥ 2 % envía al instante.
  • Monitor serie: MQTT … publicado
  • http://localhost:8090/api/v1/readings/recent: FORWARDED / ACCEPTED

5.4 · Sensor real (placa + JSN-SR04T)

  1. TRIG en GPIO 5, ECHO en GPIO 18 con divisor 1 kΩ / 2 kΩ (el eco sale a 5 V), VCC a 5 V, GND común.
  2. Credenciales WiFi en secrets.h (no se sube a git).
  3. Mide la distancia real con el tanque lleno y vacío, y calibra la separación, la altura útil y la capacidad.
  4. Prueba con objetos a 30, 60 y 100 cm y compara con lo que muestra el monitor serie.

5.5 · Comprobar en el backend

curl https://fulltank-backend.onrender.com/api/provider/tanks/<tankId>/readings \
  -H "Authorization: Bearer <JWT>"
  • La lectura aparece con quality: ACCEPTED y el nivel del tanque cambió en la web

5.6 · Resiliencia: Render dormido

Envía una lectura con Render dormido: la Edge la deja en cola (/health → queued: 1) y la reintenta (2 s, 4 s … hasta 60 s) hasta que el backend responda. La lectura llega sola, sin duplicarse.

6Plan B: el broker público se cae

  1. En .env: MQTT_URL=tcp://mosquitto:1883 y MQTT_USERNAME/MQTT_PASSWORD iguales a los de Mosquitto.
  2. docker compose up -d
  3. El ESP32 físico apunta a <IP-de-tu-PC>:1883 con esas credenciales (o usa HTTP directo a la Edge).
Wokwi no llega a tu PCWokwi en el navegador solo sale a internet. Con el plan B, prueba con la placa real o con MQTTX apuntando a localhost:1883.
